# ADR-001 — Foundation implementation choices

**Status:** Proposed; requires runtime evidence and architecture review.

1. Develop D0+D1 as a single Python package with separated executable entrypoints (`api`, `collector`, `outbox`). Future risk/order execution services will be Go services. This reduces first-phase complexity without undermining future isolation.
2. PostgreSQL is canonical, Redis a dispensable cache/limiter backend, and NATS JetStream a derived message bus with a transactional outbox.
3. Public Binance REST/WSS only; prohibit all signed/private calls or money movement.
4. Preserve market price/quantity as decimal strings. Record event/receipt clocks separately.
5. Expose warnings for stale streams and unresolved aggregate trade gaps; reject interpretations of the partial best-bid/ask stream as full depth.
6. Treat CI checks, Docker runtime acceptance, network validation and user product eligibility as separate gates.
